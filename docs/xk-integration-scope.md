# Vben 原生页面接入范围

状态：原生组件接入已实现，接口测试、类型检查与生产构建通过。浏览器验收结果单独记录，不以构建代替真实页面验收。

## 已明确范围

- 在当前 vue-vben-admin 仓库实施，复用 Vben 原生登录、布局、图标、表格、表单、抽屉、弹窗及权限能力。
- 现有后端接口决定业务字段、查询参数、返回数据、授权和数据范围；必要时为表单增加输入项。
- 不以 xk-backend/admin-web 的页面替换 Vben 页面，不修改旧前端。
- 首期接入已有后端功能：登录退出、当前身份、动态菜单、按钮权限、单位、用户、角色、菜单管理、角色功能及单位授权、用户角色绑定、锁定、重置密码、本人资料查看与改密、报表。
- 清除正式应用左侧演示菜单及对应演示数据和专用源码；共享组件仍按实际依赖保留。
- 沿用此前已明确的范围：不建设通知中心、保留空白仪表盘、暂不建设干部考核业务页面。
- 页面已有但后端未实现的能力，先确认范围再补接口。

## 已核对事实

- `playground` 包含完整的系统用户、角色、菜单、部门页面，使用 antdv-next 及 Vben 的 Page、Form、VxeGrid、Drawer、Tree；`apps/web-antd` 是使用 ant-design-vue 的基础应用。
- 后端菜单已包含 `icon` 和 `shortcutIcon`，保存参数、实体、管理返回及导航返回均已支持；普通菜单图标不需要新增同名字段，可接入原版 IconPicker。
- 原版菜单的 `activeIcon`、`keepAlive`、`affixTab`、隐藏配置、徽标、外链及内嵌页配置，在现有后端菜单模型中没有一一对应的可持久化字段。
- 后端采用 `code=SUCCESS` 响应、UUID Token、RSA-OAEP/SHA-256 密码加密；Vben 的请求层和认证状态层需要适配，不能沿用演示的 code=0、明文密码和 refreshToken 协议。
- 角色功能与单位授权已经有原子保存接口；管理员身份、菜单访问、按钮权限、单位范围保持分别处理。
- 报表菜单列表和打开接口已存在，打开后使用同源 Cookie；报表凭据不进入 URL。

## 已确认决策

| 编号 | 决策 | 结论 |

## 实现与启动

正式应用使用 `playground`，根目录 `pnpm dev` 已指向该应用，端口为 5666；`pnpm build:xk` 构建到 `playground/dist`。保留其他上游应用作为仓库原有内容，它们不是当前正式应用入口。

开发默认将 `/api` 与 `/ureport` 代理到 `http://127.0.0.1:8080`。指定隔离后端可执行 `XK_BACKEND_URL=http://127.0.0.1:18080 pnpm dev`。生产环境需将这两个路径同源代理到后端、保留 Host/Origin，并为前端 history 路由配置 index.html 回落。生产使用 HTTPS，浏览器密码加密依赖安全上下文。

后端需运行本轮新版代码及 Liquibase 010/011 迁移。旧服务没有滑块和个人资料新接口，不能与新版前端配套使用；旧 admin-web 未适配必填 captchaToken。

原生管理表单根据后端字段增加输入项；菜单使用三个独立 IconPicker。权限树父子独立选中，缺省授权组不修改，保留历史失效项回显和移除。菜单 ID 决定路由身份，普通页面仅映射已实现组件；报表页面通过后端打开接口获得同源地址。
